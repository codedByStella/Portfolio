Make public records easier to find and work with

StellaScrapes is a Python and Node.js public-record data discovery and processing platform. Its original application reached a functional MVP for searching supported Socrata datasets, preparing records, and exporting structured results. The public repository is a deliberately limited portfolio release, not the runnable application.

project overview

Public-data platforms expose useful records, but datasets differ in structure, field names, identifiers, and update practices. Reusing those records across sources requires more than issuing an API request: candidate datasets need to be found, inspected, mapped, and processed into consistent outputs.

StellaScrapes was built to bring those steps into a single local workflow. The original MVP combines Socrata data discovery, registry-based source configuration, record retrieval and processing, and structured exports. The project remains in active development; support for a source or record category depends on its actual integration and validation.

system capabilities
  • Source discoveryPython utilities inspect Socrata publishing domains and dataset metadata to identify candidate public-data sources for review.
  • Registry-driven configurationStructured configuration associates supported sources with dataset identifiers and source-specific metadata, reducing the need to hard-code every integration into the same workflow.
  • Record processingProcessing utilities prepare selected public-record data for consistent review, including normalization, deduplication, and permit-oriented handling where applicable.
  • PrioritizationRules-based scoring can help organize records for manual review. It is not a validated prediction of buyer intent, conversion, or revenue.
  • Structured exportsCSV and Excel outputs support further analysis and handoff.
  • Multiple interfacesThe original application includes a Python command-line workflow and a local browser interface backed by Node.js and Express.
public repository

The public repository is intentionally incomplete. It documents the project structure and selected supporting components while withholding proprietary implementation details, including production retrieval, query-routing, dataset-selection, and processing logic. The published code is therefore not a runnable release and should not be treated as a deployable application or a complete representation of the private working implementation.

development status

MVP achieved; active development continues. The original application reached a functional MVP, but coverage and reliability depend on individual source integrations. Dataset discovery does not automatically make a dataset supported, and heuristic field mapping requires validation. The portfolio repository is a selectively redacted snapshot rather than the production codebase.
