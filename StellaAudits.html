Turn website issues into a clear action plan

StellaAudits checks a business website for selected accessibility, search-visibility, local-search, and basic security indicators, then organizes the findings into a report. Findings include severity and explanatory context, while repeat reviews help identify what changed between recorded runs. It is a preliminary review tool, not a substitute for expert testing or a determination of compliance or security.

what it helps with

A quick website review can miss accessibility, search, or configuration problems. StellaAudits collects its checks in one report, with the evidence and severity beside each finding so the owner or developer can decide what to investigate first.

  • One readable reportAccessibility, SEO, local search, and selected security checks use a shared finding format, then feed a PDF report instead of leaving the owner to sort through separate warning lists.
  • Optional Lighthouse measurementsWhen configured and available, the PageSpeed Insights integration adds Lighthouse performance and SEO category scores. The integration also requests accessibility data, but the current implementation does not convert individual Lighthouse accessibility audits into findings. If the request is unavailable, it adds an informational notice and the standard static checks continue.
  • JS-rendering awarenessUses the amount of text in the initial HTML as a heuristic for possible client-side rendering. When the initial response contains little text, the audit adds an informational notice recommending browser review. It does not automatically downgrade or correct the other findings.
  • Prioritization scoreFindings contribute to a bounded site-health score and letter grade. Notices about audit coverage are designed to be treated separately from site defects. The scoring implementation and proprietary deduction criteria are intentionally withheld from this public source, so the exact calculation is not independently inspectable here.
  • Lead tracking & comparisonsRecorded runs are stored in a local SQLite database with score, grade, and finding snapshots. A later run can identify findings that disappeared, newly appeared, or persisted. A finding disappearing from a report does not prove the underlying issue was fixed.
  • Outreach draft generationGenerates a promotional outreach draft alongside the PDF. It is not sent automatically and is intended for human review. The draft includes sender and promotional-message details plus reply-based opt-out language; a missing mailing address triggers a warning and placeholder rather than a complete legal-compliance determination.
how it works

Most automated site-audit tools fall into one of two traps: they guess with no admission of uncertainty, or they require a full headless-browser stack just to run once. Static HTML parsing is fast and honest about what it measured, but it can be flatly wrong against a JavaScript-rendered shell, reporting "no H1, no content" against a site that's actually fine once rendered is a false, credibility-damaging finding.

The intended scoring model distinguishes site findings from notices about the audit's own coverage. Static checks run against the initial HTML, while optional Lighthouse category scores can add limited browser-rendered context when available. The public source omits the proprietary scoring implementation, so its exact treatment of every finding cannot be verified from this publication.

engineering detail

Scoring that distinguishes site findings from audit notices

An early run against a JavaScript-heavy site exposed a scoring-design issue: a notice about the audit's own coverage is not itself a defect on the audited site. The shared Finding model includes an is_meta flag to distinguish such notices. The scoring implementation is intentionally redacted from this public repository, so the precise calculation cannot be inspected here.

Publication boundary: the original scoring implementation and its proprietary deduction criteria are deliberately withheld. The public source retains the finding model and orchestration relationship, but does not expose enough code to reproduce or independently verify the score calculation.

The outreach generator also excludes metadata notices from its substantive finding summaries, so a limitation of the audit itself is not presented as a reason for a prospect to hire someone.

when a finding calls for a deeper security review

StellaAudits includes selected, basic website-security checks. If a finding warrants a broader look, StellaOpsec is a separate, dormant toolkit I have used to collect additional configuration and security indicators into a report. It can help flag questions for follow-up; it is not a service I offer, a comprehensive security audit, or a substitute for a qualified security professional. My role is to report what the tools show and hand off issues beyond my expertise, not to claim credentials or take on remediation work.
