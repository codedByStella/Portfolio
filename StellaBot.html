A desktop companion built around continuity

StellaBot is a Windows-focused Python desktop-companion prototype exploring persistent conversational identity, local memory, environmental context, voice-related components, and autonomous conversational initiative. The goal is to make interactions build on relevant prior context rather than treating every session as isolated.

Python Win32 API (ctypes) Multi-threading SQLite PowerShell (TTS)
architecture

This is more than a single model-request wrapper. The application separates conversation handling, context assembly, persistence, desktop integration, and background activity into distinct modules. It remains a prototype; the presence of these boundaries does not establish production reliability.

  • OS-level context awarenessUses Windows integration to identify foreground-window activity. Screenshots are captured and managed locally in a rolling visual reel; the model request uses a derived textual activity timeline, not the screenshot pixels.
  • Asynchronous orchestrationSeparates interface and background responsibilities, including attention and initiative routines, with lifecycle handling for application shutdown.
  • Graceful degradation & rate limitingModel-provider communication is separated from conversation and context handling. Runtime behavior still depends on provider availability, configuration, dependencies, and local execution conditions.
  • Local state persistenceUses local SQLite persistence for structured conversation and companion data, with JSON files for supporting profile, configuration, and runtime state.
  • Voice integrationVoice functionality is separated from the main conversation and interface code. The repository includes integration points and asset structure, but not every voice path is configured or verified.
the problem

StellaBot can assemble a request from the current message, recent conversation history, selected persistent memory and preferences, and temporary application context. Structured runtime data is stored locally using SQLite and JSON.

The design separates local context collection from model requests. Screenshot capture and reel management happen locally; the model receives a textual activity timeline rather than screenshot pixels. This timeline is temporary environmental context, not persistent memory.

engineering detail

Initiative & backoff

Proactive interaction is governed by idle-time and activity-state logic, including a cap on unanswered autonomous messages. These mechanisms are intended to let the companion back off when the user does not engage. Their presence in source code does not establish that every timing or interruption edge case has been validated.

To prevent the agent from talking to itself endlessly, it implements a hard cap on unanswered autonomous messages. If the user doesn't reply, the agent backs off and returns to silent observation.

conceptual logic for autonomous backoff
# Agent already tried to speak; user is busy. Go quiet. if initiative_unanswered >= INITIATIVE_MAX_UNANSWERED: continue # Visual state hasn't changed. No new reason to speak. if screen_hash == last_spoken_hash: continue # State is new and settled; ask the model if it wants to speak. reply = ask_agent(..., initiative=True) if "[QUIET]" in reply: continue

Without a backoff limit, an always-on companion can keep interrupting after the user has stopped responding. StellaBot tracks unanswered initiatives and returns to quiet observation after the configured limit.
